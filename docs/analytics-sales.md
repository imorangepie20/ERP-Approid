# Spring 영업 요약 계약

ANL-03의 수주·확정 출하·현재 수주잔고와 미수 문서 원금 분석이다.
회계 매출/원가·부분수납·수납일 이력·사업장 필터는 원천 구조가 없어 추정하지 않는다.

## 권한과 조회

`GET /api/core/analytics/sales/summary`는 기존 미수 상세 권한과 동일하게 ADMIN/SALES/ACCOUNTING만 허용한다.
비로그인401, 다른 인증 역할403이다. 기존 대시보드의 전체 인증 사용자용 매출 집계와 상세 미수 분석을 구분한다.
프런트 링크와 페이지도 이 권한을 따르며 실제 최종 권한은 서버가 검사한다.
read-only/REPEATABLE_READ로 요약·행을 같은 DB 스냅샷에서 조회한다. 업무 상태·현재고·감사를 바꾸지 않는다.

| 매개변수 | 규칙 |
| --- | --- |
| from, to | 수주일/실제 출하확정일의 포함 기간; 기본 서울 이번 달1일~오늘, 과거부터 오늘까지 최대366일 |
| itemId | 생략 전체; 양수 PK, 미존재404 |
| customerId | 생략 전체; 양수 고객사 PK, 미존재/다른 유형404 |
| keyword | 최대128자; 수주번호·고객코드/명·품번/명 부분 검색, 대소문자 무시, `%_!` 문자 그대로 |
| scope | ordered(기본: 기간 내 수주), backlog(현재 확정/생산중), receivables(현재 열린 미수에 연결된 수주) |
| sort | orderedAt,desc(기본); orderedAt/dueDate/salesOrderNo/amountKrw/openReceivableKrw + asc/desc만 허용 |
| page, size | 0-based page0~10000, size1~100(기본20), 범위 밖 페이지는 빈 행 |

잘못된 기간/날짜/필터/정렬/페이지는 trace ID를 포함한 공통 INVALID_INPUT 400, 지원하지 않는 쓰기405다.
동률 정렬은 수주번호/ID로 안정화한다. `asOf`는 UTC 조회 시각, `timeZone`은 Asia/Seoul이다.

## 금액·기간·제외 정책

- 기간 수주 건수는 수주일로 선택한 모든 상태를 포함하며 취소 건수를 별도로 반환한다.
  기간 수주액은 같은 기간 수주 금액 중 취소를 제외한다. 현재 상태 기준이며 과거 종료일 당시 상태를 복원하지 않는다.
- 기간 확정 출하액/건수는 **실제 출하확정일과 수불·미수 FK가 있는 출하완료/매출반영 문서**만 포함한다.
  배송 예정일·미확정 지시·취소·과거 미연결 이력을 매출로 추정하지 않는다. 대시보드와 같은 SQL 인식 경계를 사용한다.
- 현재 수주잔고는 확정/생산중 수주액−기간과 무관한 모든 확인된 출하액이다.
  과거 미연결 출하·초과 출하·출하완료 상태와 수량 불일치는 `historyUnknown=true`로 표시한다.
  해당 행의 현재 잔고는 null이며 확인된 잔고 합에서 제외한다. 활성 잔고 건수와 미확인 건수를 함께 보여준다.
- 현재 미수는 수주에 연결된 미수/연체 문서 원금 합, 수납완료 제외다. 연체는 **서울 오늘 이전** 기일만 해당한다.
  저장된 연체 표식/일수 대신 기일로 계산한다. 부분수납이나 수납일 기록이 없어 실제 잔액/기간 수납액을 만들지 않는다.
- 출하와 미수는 각각 수주별 사전 집계 후 연결한다. 여러 출하×여러 미수의 조인 곱으로 원금/매출을 중복 계산하지 않는다.
- 요약은 품목·고객·검색의 전체 결과이며 목록 범위와 페이지의 영향이 없다.
  현재 잔고/미수 금액과 해당 목록에는 날짜 필터를 적용하지 않는다. 주문 수량/출하 수량은 행별 기본 단위로 표시하며
  kg/EA 등을 합산하지 않는다. 원화는 정수이며 JS 안전 정수 범위를 넘는 응답은 오류로 표시해 반올림 오해를 막는다.
- 미연결 출하 제외 건수는 선택된 수주에 연결된 이력에 대해 기간과 무관하게 계산한다.
  수주가 없는 미수는 품목/검색/기간을 알 수 없어 원금 집계에서 제외하고, **고객 필터만 적용한** 제외 건수를 반환한다.
  제외 건수는 수납완료를 포함한 모든 상태의 미연결 문서다. 품목/검색 결과와 이 제외 건수의 범위가 다름을 화면 근거에 표시한다.

## 화면과 업무 연결

`/analytics/sales`는 공통 달력·고객/품목 마스터 선택·검색 적용·목록 범위·정렬·페이지·현재값 새로고침을 제공한다.
로딩/빈 결과/trace 오류·재시도와 미확인 이력 경고를 표시한다. 시드 수치나 DataContext fallback은 없다.
대시보드 링크는 적용된 품목 ID를 전달하되 과거 KPI 기간을 현재 잔고로 혼동하지 않도록 기간은 전달하지 않는다.

행의 `/sales/orders?keyword=...`는 실제 수주 조회, `/sales/shipments?salesOrderId=...`는 실제 연결 출하 조회로 이동한다.
미수 원금이 표시되더라도 아직 프로토타입인 미수 화면으로 링크하거나 수납 동작을 새로 추가하지 않는다.
FIN-01의 실제 수납 이력/부분수납 구현은 별도 단위다.

검증 대상은 `SalesSummaryIntegrationTest`, `salesAnalysis.test.ts`, `SalesAnalysis.test.tsx`,
수주/출하 URL 필터 회귀와 실제 Chromium 거래 흐름이다. 검증 결과는 `phase1-e2e.md`에 기록한다.
재고/사업장 분석이 남아 있으므로 ANL-03 전체 완료로 표시하지 않으며 미푸시 변경의 원격 CI 성공을 추정하지 않는다.
